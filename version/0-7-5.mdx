September 10, 2026

#### **1. Turn any database into an automated workflow**

Your un-automated databases now display an **Add a workflow** button in the toolbar. Clicking it starts a quick, guided chat setup where DeepVista helps you choose what data to track, sources the answers, and keeps your columns populated automatically.

Get started by opening any database and clicking `Add a workflow` in the toolbar.

![Adding a workflow to a database from its toolbar](/images/release-0-7-5-database-workflow-automation.gif)

#### **2. Set up new projects in a few guided steps**

The two-step project setup from 0.7.4 is now a short guided flow, and new accounts go through the same one. It walks you through naming your project, choosing an inbound or outbound focus, and opening your first workbench with starter tables and prompts ready to go.

Get started by clicking `+ New Project` on your dashboard.

![Setting up a new project through the guided step-by-step flow](/images/release-0-7-5-guided-project-setup.gif)

#### **3. Jump from a workflow's Output node to the database it fills**

Want to see the records your workflow just produced? In the workflow diagram, click the `Output` node and a popover names the database its runs land in, under **Lands in**. Click that card to open the database in a new tab, so the diagram you were reading stays where it is.

DeepVista finds the database from the workflow's own run history, so this appears once the workflow has run at least once and its runs write to a whole database. A workflow that has never run, or one scoped to individual rows, shows `View all outputs` instead. If a workflow feeds several databases, the most recently updated one is named.

![Clicking a workflow's Output node to open its target database](/images/release-0-7-5-workflow-output-to-database.gif)

#### **4. Open your rollup database automatically**

Workbenches now open directly to your aggregated database view. When you open a workbench to check leads, contacts, or research, your rollup table appears right away so you can get to work without an extra click. Close the panel and it stays closed for the rest of that visit.

Try it by navigating to any workbench from your sidebar.

![Opening a workbench directly into its rollup database view](/images/release-0-7-5-rollup-database-auto-open.gif)

#### **5. Your background runs report their real status**

A dispatched run used to keep whatever status it was created with, so a run that had already errored could still sit under a green *Running* label. Each run now records its status as it goes: an error or a partly-failed run shows the red dot, a run that is queued and not yet picked up reads as *Queued* rather than running, and a cancelled run no longer claims a success it did not have. Dispatched runs are also linked to their chat session now, so you can open the run's chat to see what happened.

The `Runs` list refreshes when you come back to the tab rather than streaming, and runs dispatched before this release keep their old frozen status.

Try it in any workflow from the `Runs` tab.
