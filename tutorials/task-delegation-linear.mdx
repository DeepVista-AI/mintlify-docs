## Overview

By the end, DeepVista will file Linear tickets automatically from a cloud-triggered prompt, while your Linear API token never leaves your own machine.

When a cloud agent needs a local environment, a specific CLI, or credentials such as an API key, DeepVista packages the work as a **task** context card and dispatches it to a CLI runner on your connected machine.

This tutorial shows how to configure that flow so Linear tickets are created headlessly on your machine.

With your machine connected and `deepvista tasks run` polling, configure Linear API credentials in the same terminal session (or your shell profile):

```bash
export LINEAR_TOKEN="your_linear_api_token"
```

Create a personal API key from [Linear → Settings → API](https://linear.app/settings/api). The local agent reads this variable on your machine and does not upload the credential to DeepVista.

## Step-by-step guide

<Steps>
  <Step title="Create a task-type context card">
    In DeepVista, a Task is essentially a Context Card with `type: "task"` and `status: "pending"`. Its `description` contains a YAML metadata prefix along with the specific prompt you want to execute.

    **Example card configuration:**
    - **Type**: `task`
    - **Status**: `pending`
    - **Title**: `Create a test Linear ticket`
    - **Description**:
    ```yaml
    ---
    agent_id: "your-machine-id"  # Fill in the local Machine ID you connected
    agent_role: "engineering"
    ---
    Please create a test Linear ticket.

    To do this:
    1. Search the local machine (environment variables, config files, or helper tools) for any Linear API credentials (such as LINEAR_API_KEY, LINEAR_TOKEN, etc.).
    2. If credentials are found, use the Linear GraphQL API (via curl or python) to create a new ticket in an active workspace.
       - Title: "DeepVista Test Ticket"
       - Description: "This is a test ticket filed automatically by DeepVista agent task delegation."
    3. Report the status of the ticket, the ticket key/ID, or a URL to the ticket if successfully created.
    ```
  </Step>
  <Step title="Cloud dispatch and local claim">
    1. The cloud agent stores this task card in the database.
    2. The local CLI agent (polling via `deepvista tasks run`) retrieves the pending task and invokes Claude locally to execute the prompt:
       - Claude checks the local environment variable `LINEAR_TOKEN`.
       - It sends an `issueCreate` request to Linear via the GraphQL API.
  </Step>
  <Step title="Capture the results">
    Once execution completes, the local agent writes the run log (`## Run`) and the final result card (`type: "note"`) back to DeepVista, and automatically updates the Task's `status` to `completed`.

    **Example final result**:
    - **Key**: `DV-1373`
    - **Title**: DeepVista Test Ticket
    - **URL**: `https://linear.app/deepvista/issue/DV-1373/deepvista-test-ticket`
  </Step>
</Steps>

## Why this pattern helps

- **Stay secure:** API tokens and SSH keys stay on your machine instead of being uploaded to the cloud.
- **Reach local resources:** The runner can use your local filesystem, databases, or internal services that only exist on your network.
- **Clean up tests:** After you confirm the flow, delete the test Linear ticket (`DV-…`) so your board stays tidy.
